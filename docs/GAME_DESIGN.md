# CORE BREAKER 게임 기획서

> 문서 버전: 1.0
>
> 기준 빌드: 2026-07-21 `main`
>
> 상태: 20웨이브 플레이 가능 / 콘텐츠·밸런스·가독성 검증 단계

## 1. 한 줄 소개

공 하나를 직접 조준해 고정 블록 패턴을 돌파하고, 웨이브마다 스킬을 쌓아 후반 연쇄 폭발력을 만드는 20웨이브 빌드형 브릭 브레이커.

## 2. 디자인 목표

1. **블록을 읽는 플레이**: 블록 특성과 보호 방향이 색·형태·이펙트만으로 구분되어야 한다.
2. **공 하나에 집중**: 기본 공을 1개로 유지해 궤적, 스킬 준비 상태, 충돌 결과를 읽기 쉽게 한다.
3. **조준 가능한 반사**: A/D로 패들을 이동하고 마우스로 다음 반사 방향을 정해 수비와 공격을 함께 판단한다.
4. **명확한 성장**: 매 웨이브 선택한 스킬이 직접 피해, 연쇄, 제어, 소환, 방어로 분명한 변화를 만든다.
5. **후반 폭발력**: LV3 진화와 보스 궁극기가 연쇄를 확장해 후반에는 의도적인 대규모 반응을 허용한다.
6. **측정 가능한 밸런스**: 실제 런타임 관찰과 결정론적 고정 스텝 벤치마크로 스킬·웨이브 영향을 비교한다.

## 3. 플레이 흐름

```text
타이틀
  → 시작 스킬 1개 선택
  → 웨이브 플레이
  → WAVE CLEAR 연출
  → 일반 스킬 또는 보스 궁극기 선택
  → 다음 웨이브 전환 연출
  → W20 클리어 또는 CORE 0
  → 결과
```

### 시작

- 일반 선택 풀에서 시작 스킬을 정확히 1개 선택한다.
- 선택 즉시 W1을 시작한다.
- 경험치, 시작 스킬 2개 선택, 공 소비 비용은 사용하지 않는다.

### 웨이브

- 총 20개 고정 웨이브로 구성한다.
- 각 웨이브는 12열, 최대 8행의 패턴을 사용한다.
- 제한시간은 없다. 플레이 시간이 길어질수록 공 속도가 초당 1%씩 증가하며 최대 150%에 도달한다.
- 파괴 가능한 블록을 모두 제거하면 즉시 클리어한다. 파괴 불가 블록은 클리어 판정에서 제외한다.
- 클리어 시 다음 웨이브 블록을 미리 만들지 않는다. 보상 선택이 끝난 뒤 전환 중 생성한다.
- W10은 중간 보스, W20은 최종 보스다.

### 실패와 재개

- 기본 CORE는 8이다.
- 기본 공을 놓치면 CORE 1을 즉시 잃고 패들 위에서 새 공을 소환한다.
- 임시 공이 사라지는 것은 CORE 손실로 처리하지 않는다.
- CORE가 0이 되면 게임 오버다.
- 체력은 별도 바나 하단 HUD가 아니라 플레이어 패들 내부의 `◆ 숫자`로 표시한다.

## 4. 조작과 물리

### 입력

- `A/D`: 패들 좌우 이동
- 마우스: 패들에 닿은 공이 향할 반사 방향 조준
- 조준 보조선은 실제 허용 각도와 길이 제한을 반영한다.

### 기본 수치

- 논리 해상도: 900×600
- 기본 패들 폭: 128px
- 패들 이동속도: 460px/s
- 기본 공 속도 성분: X 240, Y 320
- 최소 수직 속도 비율을 보장해 좌우 왕복과 수평 고착을 방지한다.
- 패들 측면 접촉을 완화해 가장자리에서도 정상적으로 반사한다.

### 공 상태

- 모든 웨이브는 기본 공 1개로 시작한다.
- 아이템이나 스킬로 생성된 임시 공은 회색 몸체와 낮은 강도의 스킬 이펙트로 구분한다.
- 스킬은 공별 쿨타임을 가진다. 준비된 스킬은 공 주변 이펙트와 쿨타임 게이지로 표시한다.
- 폭발 블록이 공을 밀어내며 발생시키는 가속은 중첩되지 않고 1.25초 후 현재 정상 속도로 복원된다.
- 블랙홀 안에서 변한 속도는 블랙홀이 끝날 때 진입 전 기준 속도로 복원된다.

## 5. 웨이브와 보스

### 난이도 곡선

- W1~W5: 기본 블록, 가드, 반사, 폭발, 파괴 불가를 한 종류씩 학습한다.
- 최초 반사 블록은 W3의 가장 아래 행에 배치해 보호면을 읽게 한다.
- W6~W9: 회복과 여러 특성을 조합하고 행 수를 5행까지 확장한다.
- W11~W15: 6행 패턴과 높은 밀도, 반사·회복 조합을 사용한다.
- W16~W19: 7행 패턴, 파괴 불가 프레임, 다중 특성 조합을 사용한다.
- 후반 블록 HP는 웨이브 구간 배율과 각 웨이브의 HP 배율을 함께 적용한다.

### 보스

- W10과 W20에 중앙 고정형 보스 코어가 등장한다.
- 보스 코어는 내려오지 않으며 주기적으로 주변에 공격 블록 패턴을 생성한다.
- 보스와 파괴 가능한 증원 블록을 모두 제거해야 클리어된다.
- 보스 HP와 공격 주기는 Balance 설정의 `bossBaseHp`, `bossHpPerStage`, `bossAttackInterval`, `bossAttackAcceleration`을 기준으로 계산한다.
- 보스 클리어 후에는 일반 보상 대신 해당 직업의 궁극기 선택지를 제공한다.

## 6. 블록

| 코드 | 종류 | 규칙 |
|---|---|---|
| `n` | 일반 | HP가 0이 되면 파괴된다. |
| `h` | 강화 일반 | 일반 블록보다 높은 기본 HP를 가진다. |
| `g` | 가드 | 첫 번째 유효 피격을 1회 무시한 뒤 일반적으로 피해를 받는다. |
| `e` | 폭발 | 파괴 시 주변 블록에 즉발 피해를 주고 공을 밀어낸다. 연속 폭발이 가능하다. |
| `x` | 파괴 불가 | 모든 피해를 무시하며 패턴과 경로 설계에 사용한다. 클리어 대상이 아니다. |
| `c` | 회복 | 일정 시간마다 범위 안의 블록을 최대 HP까지 회복한다. |
| `r` | 반사 | 아래에서 위로 들어오는 공격을 보호면에서 피해 없이 반사한다. 측면·위쪽 공격이나 특성 봉인으로 공략한다. |
| `.` | 빈칸 | 블록이 없는 경로다. |

반사 블록은 블록 바깥쪽 보호선으로 방어 방향을 표현한다. 회복, 화상, 빙결, 봉인 등 상태가 적용된 블록에는 숫자 변화와 별도의 상태 이펙트를 표시한다.

## 7. 아이템

아이템은 블록에서 드롭되어 아래로 떨어지고 패들이 획득한다. 아이템 보유 블록은 색과 기호로 미리 구분한다.

| 아이템 | 효과 |
|---|---|
| MULTI BALL | 현재 패들의 효과를 일부 이어받는 임시 공 1개를 생성한다. 웨이브 종료 시 제거한다. |
| AUTO BARRIER | 10초 동안 바닥 근처에 자동 반사 장벽을 생성한다. |
| CORE REPAIR | 현재 CORE를 최대치 안에서 1 회복한다. |
| COOLDOWN RESET | 현재 모든 공의 스킬 쿨타임을 즉시 준비 상태로 만든다. |

멀티볼은 웨이브별 고정 예산과 드롭 배치를 사용해 밸런스 비교가 가능해야 한다. 행운은 아이템이 없는 블록의 추가 드롭 확률만 증가시킨다.

## 8. 스킬 시스템

### 공통 규칙

- 스킬 레벨은 LV1~LV3이다.
- 일반 직업 스킬은 공별 쿨타임이 준비된 블록 충돌에서 발동한다.
- 공용 스킬은 획득 즉시 상시 적용한다.
- 스킬은 패들에 충전하거나 반사 횟수를 세지 않는다.
- 패들 위에는 스킬 아이콘을 표시하지 않는다.
- 보유 스킬은 화면 왼쪽에 `아이콘 × Lv`로 표시한다.
- LV3는 회전 없이 테두리, 색, 부드러운 글로우로만 강조한다.
- LV3 직업 스킬은 수치 상승 외에 고유 진화 규칙을 얻는다.
- 일반 웨이브는 일반 스킬을, 보스 웨이브는 궁극기를 보상한다.

### 스킬 구성

| 계열 | 일반 스킬 | 궁극기 | 핵심 플레이 |
|---|---:|---:|---|
| 전사 | 5 | 2 | 직접 피해, 충격파, 처형, 가드 파괴, CORE 방어 |
| 궁수 | 5 | 2 | 임시 화살, 관통, 도탄, 집중 공격, 약점 피해 |
| 법사 | 5 | 2 | 화상, 연쇄 번개, 빙결, 블랙홀, 특성 봉인 |
| 공용 | 11 | 0 | 자석, 드롭률, 패들, 코어, 공과 스킬 전역 강화 |

시작 및 일반 웨이브 선택 풀은 직업 일반 스킬 15개와 공용 스킬 11개, 총 26개다. 궁극기 6개는 보스 보상 전용이다.

### 전사

- 강타: 준비된 직접 타격 피해 증가
- 충격파: 충돌 지점 주변 즉발 피해
- 처형: 일정 체력 이하 일반 블록 즉시 파괴
- 분쇄: 가드 제거 및 특수 블록 추가 피해
- 철벽: 일정 주기마다 CORE 피해를 막는 방어막 획득
- 대지 분쇄: 주변 여진을 강화하는 궁극기
- 광전사: 모든 공의 피해와 속도를 강화하는 궁극기

### 궁수

- 연사: 일정 시간 유지되는 임시 화살 생성
- 관통 화살: 여러 블록을 연속 관통
- 도탄 화살: 주변 위험 블록으로 연쇄
- 집중 사격: 같은 블록 재공격 강화
- 약점 사격: 준비된 직접 타격 배율 증가
- 화살비: 보유 궁수 스킬을 활용한 일제 사격 궁극기
- 무한 탄창: 임시 화살 생성량을 확장하는 궁극기

연사의 임시 화살은 LV3 이전에는 다른 스킬을 상속하지 않는다. LV3부터 상속과 재귀 생성이 가능하지만 세대마다 생성 쿨타임이 증가하며 파티클·이펙트 풀로 렌더 부하를 제한한다.

### 법사

- 화염구: 주변 블록 점화, 지속 피해, 회복 차단
- 연쇄 번개: 주변 블록 연결 피해
- 빙결 표식: 다음 피격 강화와 특성 일시 봉인
- 블랙홀: 상단에 공을 끌어당기는 중력장 생성
- 마력 봉인: 가드·회복·반사 기능을 일정 시간 봉인
- 원소 폭풍: 화염·번개·빙결을 함께 적용하는 궁극기
- 메테오: 상태이상 수에 비례해 운석을 생성하는 궁극기

### 공용

- 아이템 자석, 행운
- 패들 확장, 패들 가속
- 코어 강화, 콤보 증폭
- 공 거대화, 공격 강화
- 범위 증폭, 연계 증폭, 재사용 가속

공용 스킬은 모두 중립 회색을 사용하고, 카드에서는 실제 변경 수치만 강조색으로 표시한다.

## 9. UI와 피드백

- 타이틀 전에는 인게임 HUD를 표시하지 않는다.
- WAVE와 경과시간은 플레이 영역 상단의 독립 위치에 배치한다.
- CORE 수치는 플레이어 패들 안에 표시한다.
- 스킬 로드아웃은 화면 왼쪽에 표시한다.
- 스킬 카드의 기본 정보는 한국어 이름과 현재/다음 수치로 제한하고 상세 설명은 호버로 제공한다.
- 공 몸체 색은 기본 공과 임시 공의 구분만 담당한다. 스킬 종류는 공 주변 이펙트로 구분한다.
- 피해 숫자, 폭발 범위, 연쇄 연결선, 상태이상, 회복 숫자 변화를 충돌 지점에 직접 표시한다.
- 화면 흔들림과 사운드는 일반 충돌, 파괴, 강한 스킬, 궁극기, 보스, CORE 피해 순으로 강도를 구분한다.
- 전체화면을 지원한다.

## 11. 벤치마크

- 기본 모드는 WATCH RUN이다. 실제 게임 Canvas와 런타임에서 봇의 플레이를 관찰한다.
- HEADLESS는 렌더링 없이 좌표 기반 120Hz 고정 스텝 엔진을 Worker에서 실행한다.
- 봇은 플레이어와 같은 권한만 가진다: 패들 좌우 이동과 조준점 지정.
- 봇은 공 낙하지점 예측, 위험 블록 우선순위, 파괴 불가 회피, 반사 블록 뱅크 샷, 안전한 아이템 회수를 사용한다.
- 동일 시드와 설정은 동일 결과를 만들어야 한다.
- 결과에는 정책 버전, 엔진 버전, 웨이브별 클리어 시간, CORE, 공 수, 점수, 선택 스킬과 스킬별 발동·피해·처치를 기록한다.

세부 구조는 [벤치마크 및 봇 파이프라인](BENCHMARK_PIPELINE.md)을 따른다.

## 12. 폐기된 규칙

다음 규칙은 현재 게임에 사용하지 않는다.

- 경험치와 레벨업 드롭
- 시간제한 종료 시 남은 블록의 CORE 일괄 공격
- 일정 시간마다 한 줄씩 내려오는 무한 웨이브
- 고스트 패들과 과거 플레이 중첩
- 영구 중립 반사 바닥
- CORE LINE 도달 즉시 게임 오버
- 스킬 선택 시 공 소비
- 패들 반사 횟수 기반 스킬 충전
- 시작 스킬 2개 선택
- 패들 위 스킬 아이콘과 카운터 HUD

## 13. 현재 밸런스 검증 과제

1. W6 이후 패턴 밀도와 회복·반사 조합의 평균 클리어 시간
2. LV3 연쇄 진화가 만드는 무한 반응의 성능 상한과 가독성
3. 전사·궁수·법사 빌드의 W20 도달률 차이
4. 방어·제어 계열과 직접 피해 계열의 선택 가치
5. 보스 증원 패턴별 정체 구간과 CORE 손실률
6. 멀티볼·임시 화살 증가 시 프레임 시간과 이펙트 풀 사용량
7. 실제 플레이와 HEADLESS 결과의 지속적인 패리티 검증

## 15. 변경 관리 원칙

- 기능 변경은 구현 → 집중 테스트 → 전체 빌드/테스트 → 문서 갱신 → 기능 단위 커밋 순으로 마무리한다.
- Skill Lab과 Stage Lab에서 저장한 값은 실제 게임과 벤치마크가 같은 설정을 읽어야 한다.
- 구현과 문서가 다르면 구현을 현재 상태로 확인한 뒤 문서를 즉시 갱신한다.
- 벤치마크 데이터에는 규칙·정책·엔진 버전을 기록해 서로 다른 버전의 결과를 섞지 않는다.
